
# Performance Optimization Plan — PYQ & Syllabus Loading

## Root Cause

Your server is on Render (free tier, no cold starts thanks to UptimeRobot). The delay comes from:
1. **Every page mount = fresh HTTP request to Render** — no browser caching at all
2. **Syllabus query does a full COLLSCAN** — no `isActive` index, degrades as data grows
3. **PYQ query lacks optimal compound index** — MongoDB can't filter + sort in one pass
4. **Department PYQ page fetches ALL departments** just to find one

With 100 users, SWR (browser-only cache) is perfect — each user gets instant revisits, server only gets hit on first visit or background revalidation.

## Steps

### Step 1: Install SWR + create fetcher
- `npm install swr` in `/client`
- Create `/client/lib/fetcher.ts` — a simple axios-based SWR fetcher

### Step 2: Add SWR to 3 client pages (replace useState+useEffect)
- **`client/app/pyq/[departmentId]/page.tsx`** — 4 parallel `useSWR` hooks (departments, branches, papers, sessions)
- **`client/app/resources/syllabus/page.tsx`** — 1 `useSWR` hook for syllabus
- **`client/app/pyq/page.tsx`** — 1 `useSWR` hook for departments
- All with `revalidateOnFocus: false` to avoid unnecessary refetches
- Loading/error states handled via SWR's built-in `isLoading` and `error`

### Step 3: Add `GET /api/departments/:id` endpoint
- `server/src/controllers/departmentController.js` — add `getDepartmentById`
- `server/src/routes/departments.js` — add public route
- `client/lib/api.ts` — add `departmentApi.getById()`
- Update `[departmentId]/page.tsx` to use `getById` instead of `getAll` + client `.find()`

### Step 4: Add missing MongoDB indexes
- **`server/src/models/Syllabus.js`** — add `{ isActive: 1, createdAt: -1 }` compound index
- **`server/src/models/PYQPaper.js`** — add `{ departmentId: 1, verified: 1, isActive: 1, year: -1, downloads: -1 }` compound index
- Mongoose auto-creates indexes on server restart — zero downtime

### Expected Impact
| Metric | Before | After |
|--------|--------|-------|
| Repeat page visit | Full re-fetch from Render every time | **Instant** (browser cache), silent background refresh |
| Syllabus DB query | Full table scan | Index scan |
| PYQ DB query | Partial index + in-memory sort | Single compound index |
| Dept lookup (PYQ page) | Fetch all departments, find one client-side | Single document lookup by ID |
| Server load at 100 users | Every navigation = server hit | First visit only per user (SWR caches the rest) |
