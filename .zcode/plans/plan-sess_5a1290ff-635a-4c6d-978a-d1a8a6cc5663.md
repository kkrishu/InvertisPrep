## Goal
Make Google login in the WebView app actually work. The webapp authenticates with a **JWT in `localStorage`** (not cookies), so the Kotlin app must inject that JWT into the WebView's `localStorage` via a JS bridge — replacing the current broken cookie injection.

## Changes

### 1. Webapp — `client/app/login/page.tsx` (lines 79-85)
Add the `user` object (base64, unicode-safe) to the deep link alongside `token`, and drop the misleading `session=true`:
```ts
if (isWebViewAuthFlow && typeof window !== 'undefined') {
  const callbackUrl = new URL('invertisprep://auth/callback');
  callbackUrl.searchParams.set('token', response.data.token);
  const userB64 = btoa(encodeURIComponent(JSON.stringify(response.data.user))
    .replace(/%([0-9A-F]{2})/g, (_, p) => String.fromCharCode(parseInt(p, 16))));
  callbackUrl.searchParams.set('user', userB64);
  window.location.replace(callbackUrl.toString());
  return;
}
```
Why: `AuthContext.tsx:31` requires **both** `token` **and** `user` in localStorage, so both must come back through the deep link.

### 2. Kotlin — `AuthHelper.kt` (`parseCallback`, lines 94-113)
- Prioritize `token` over `session` (so `?token=…&session=true` no longer drops the token).
- Add `user: String?` (base64) to `CallbackResult` and parse the `user` query param.

### 3. Kotlin — new `AuthStorage.kt`
Small `SharedPreferences` wrapper so login persists across app restarts (your choice: "Until logout").
- `save(ctx, token, user)` — store both.
- `getToken(ctx)`, `getUser(ctx)` — read back.
- `clear(ctx)` — wipe.

### 4. Kotlin — `MainActivity.kt`
**Remove** the cookie injection (`CookieSyncHelper.setCookie("authjs.session-token", …)` at line 179). **Add** a localStorage JS bridge instead:
- On successful deep link: decode base64 `user`, `AuthStorage.save(...)`, set `pendingInjection = true`, reload the webapp.
- In `onPageFinished`: if `pendingInjection`, run `evaluateJavascript` with an IIFE that sets `localStorage.token` and `localStorage.user`, then `reload()` once. Clear the flag to avoid a loop.
- Add a `jsString()` helper to safely embed values into JS (escape `\`, `"`, `\n`, `\r`).

### 5. Kotlin — `MainActivity.kt` cold start
In `onCreate`, after WebView setup: if `AuthStorage.getToken()` is non-null, read `localStorage.token` via JS; if missing/empty, set `pendingInjection = true` and reload. Keeps users logged in across relaunches without a reload flash when localStorage already has the token.

## Not changing
- `CookieSyncHelper` left as-is (harmless, configured but no longer used for auth).
- Logout left to the webapp (your choice).

## Verification
1. Login via Google in Custom Tab → returns → WebView shows authenticated home, Navbar shows user.
2. Force-stop + relaunch → still logged in, no reload flash.
3. Clear app data → relaunch → login again works from scratch.
4. Open a protected page (e.g. PYQ) → loads as the user, no re-login prompt.
